Documentation

How my Element 5 scenes, the Outskirts and the Bunker, were designed and built: the concept, key code, the GUI and the scene transitions.

01

Overview

Escape is a short zombie-survival game made of two original levels. In the Outskirts the player searches a night-time valley for a keycard and then reaches a bunker in the hills. Walking into the bunker door loads the Bunker, an indoor level where the player has to reach a radio and call for rescue. A main menu and a rescue screen sit either side of the two levels.

ScenesMenu → Outskirts → Bunker → Rescue

02

Concept & Design

All five elements share one setting: a town overrun by zombies. Element 5 turns that setting into a small game with a clear goal: get out alive. The two levels were designed to contrast with each other. The Outskirts is open, foggy and lit by the moon and fire, while the Bunker is enclosed, dark and lit by flickering strip lights and a spinning red siren.

Design decisions

  • Emphasis: the bunker door is the focal point of the Outskirts, with a pulsing red light so it can be seen through the fog. The burning car marks where the keycard is.
  • Rhythm and repetition: dead trees are repeated around the valley as instances at different sizes and angles.
  • Pace: fog limits how far the player can see, so zombies appear out of the dark. The Bunker's side rooms hide zombies around corners.
  • Colour: a muted green-grey palette with warm firelight, red danger lights and a cyan keycard so the important objects stand out.
  • Consistency: both levels use the same player, zombies, HUD and pause menu, so the game feels like one piece.

03

Project Structure

Each scene is a function that builds and returns a Scene. Code used by more than one element, such as the player, zombies, props and GUI, lives in src/shared/, so each level file only has to describe its own layout and rules. Gameplay used by both levels (damage, medkits, pausing and dying) is in a single Level class.

Folder structure
babylon-src/
├── element5/index.html        // the page that loads Element 5
└── src/
    ├── element5/
    │   ├── main.ts             // creates the engine and the scenes array
    │   ├── gameState.ts        // health, keycard and timer shared between scenes
    │   ├── level.ts            // damage, medkits, pause and death (used by both levels)
    │   ├── menuScene.ts        // scene 0 - main menu
    │   ├── outskirtsScene.ts   // scene 1 - the Outskirts
    │   ├── bunkerScene.ts      // scene 2 - the Bunker
    │   └── endingScene.ts      // scene 3 - rescue
    ├── shared/                 // code reused by Elements 1-5
    │   ├── sceneManager.ts     // scenes array + setSceneIndex()
    │   ├── player.ts           // animated third-person player
    │   ├── zombie.ts           // procedural zombie and chase behaviour
    │   ├── props.ts            // merged-mesh props (houses, cars, trees...)
    │   ├── environment.ts      // skybox, fog, moonlight, terrain, fire
    │   ├── hud.ts / gui.ts / menu.ts   // Babylon GUI
    │   └── audio.ts            // sound on/off + SoundBank
    └── assets/                 // textures, skybox, height map, audio

04

Scene One: The Outskirts

The Outskirts is built on terrain generated from a greyscale height map: the centre is flat and the edges rise into hills. Houses, wrecked cars and trees are placed on the terrain using getHeightAtCoordinates, and a burning car uses two particle systems (fire and smoke) with a flickering point light.

Building on the terrain

outskirtsScene.ts
// Terrain generated from a greyscale height map (shared/environment.ts)
const terrain = await createTerrain(scene, {
    size: 140,
    subdivisions: 120,
    maxHeight: 16,
    material: lib.ground(14)
});
const heightAt = (x: number, z: number) => terrain.getHeightAtCoordinates(x, z);

// Helper that stands any mesh on the terrain
const place = (mesh: { position: Vector3 }, x: number, z: number, lift = 0) =>
    mesh.position.set(x, heightAt(x, z) + lift, z);

const car = createCarWreck(scene, lib);
place(car, -11, 4);
createFire(scene, new Vector3(-11, heightAt(-11, 4) + 1, 4), 1);

createTerrain returns a promise that resolves once the height map has loaded, so the scene waits for it before placing anything. The place helper reads the ground height at an x/z position and stands the mesh on it. The same heightAt function is passed to the player and the zombies so they walk over the hills.

Collecting the keycard

outskirtsScene.ts
// Keycard pickup - checked every frame
scene.onBeforeRenderObservable.add(() => {
    if (keycard.isEnabled()) {
        keycard.rotation.y += 0.03;
        keycard.position.y = keyBase + Math.sin(time * 2) * 0.1;
        if (flatDistance(player.position, keycard.position) < 1.7) {
            gameState.hasKeycard = true;
            keycard.setEnabled(false);
            sounds.play("pickup");
            hud.showMessage("KEYCARD FOUND", 2);
            updateObjective();
        }
    }
});

Every frame the keycard spins and bobs. When the player gets within 1.7 m, it is disabled, gameState.hasKeycard is set, a sound plays and the HUD objective changes to “Get to the bunker door”. Storing this in gameState means it is remembered if the level is paused or restarted.

05

Scene Two: The Bunker

The Bunker is an indoor level built entirely from boxes. The layout is described as data, an array of walls, and one loop builds them all. That makes it easy to change the layout without writing new code.

Building the level from data

bunkerScene.ts
// [centre x, centre z, width (x), depth (z)]
const WALLS: [number, number, number, number][] = [
    // outer walls
    [-7, 0, 0.4, 44],
    [7, 0, 0.4, 44],
    [0, -22, 14.4, 0.4],
    [0, 22, 14.4, 0.4],
    // left partition with doorways at z -12..-9 and 2..5
    [-2.5, -17, 0.3, 10],
    [-2.5, -3.5, 0.3, 11],
    [-2.5, 13.5, 0.3, 17]
    // ...
];

for (const [x, z, w, d] of WALLS) {
    const wall = MeshBuilder.CreateBox("wall", { width: w, height: WALL_H, depth: d }, scene);
    wall.position.set(x, WALL_H / 2, z);
    wall.material = lib.brick(Math.max(w, d), WALL_H);
    wall.checkCollisions = true;
}

Each wall gets a brick material whose texture is tiled to suit its length, so the bricks stay the same size on long and short walls. checkCollisions stops the player and zombies walking through walls, and the third-person camera has collisions turned on so it doesn't clip through them either.

Emergency lighting

bunkerScene.ts
// Rotating red emergency light: a spot light parented to a spinning node
const sirenPivot = new TransformNode("sirenPivot", scene);
sirenPivot.position.set(0, WALL_H - 0.4, 19.5);
const sirenLight = new SpotLight(
    "sirenLight",
    Vector3.Zero(),
    new Vector3(1, -0.4, 0),
    Math.PI / 2.5,
    4,
    scene
);
sirenLight.parent = sirenPivot;
sirenLight.diffuse = new Color3(1, 0.1, 0.05);

scene.onBeforeRenderObservable.add(() => {
    sirenPivot.rotation.y += (engine.getDeltaTime() / 1000) * 2.5;
});

The siren is a spot light attached to an empty TransformNode. Rotating the node every frame sweeps the red light around the radio room. The ceiling lights use a flicker function that varies their intensity and occasionally cuts them out completely.

06

GUI Elements

All menus and the HUD use Babylon GUI on a full-screen AdvancedDynamicTexture, with idealHeight = 720 so they scale to any screen. The HUD shows a health bar, the keycard status, the current objective, a SOUND button and a PAUSE button. Centre-screen messages fade out on their own.

GUI responding to scene events

level.ts
// GUI reacting to scene events (element5/level.ts)
for (const zombie of this.o.zombies) {
    const d = zombie.distanceTo(player.position);
    if (d < 1 && this.hurtCooldown <= 0) {
        gameState.health -= ZOMBIE_DAMAGE;
        this.hurtCooldown = 1;
        hud.flashDamage(); // red full-screen flash
        hud.setHealth(gameState.health); // shrinks the health bar
        sounds.play("hit");
        if (gameState.health <= 0) this.die();
    }
}

When a zombie reaches the player, the health bar shrinks, the screen flashes red and a hit sound plays. A one-second cooldown stops the player losing all their health at once. Health is stored in gameState, so it carries over from the Outskirts into the Bunker.

Pop-up panels

level.ts
// Pop-up panel with buttons (shared/hud.ts)
hud.showPanel(
    "YOU DIDN'T MAKE IT",
    "The dead got you. Try again?",
    [
        { label: "TRY AGAIN", primary: true, onClick: () => this.restart() },
        { label: "MAIN MENU", onClick: () => this.o.manager.setSceneIndex(SCENES.menu) }
    ],
    "#ff4a3a"
);

Pause, game-over and win screens all use one showPanel method that takes a title, subtitle and a list of buttons. Each button is just a label and a function, which keeps the menus short to write.

07

Scene Transitions

Following the approach from the module, the scenes are stored in an array and setSceneIndex switches between them. Each entry is a function that builds its scene, so a scene is only created when it's needed and is rebuilt fresh on restart.

The scenes array

main.ts
// element5/main.ts
const engine = createEngine();
const manager = new SceneManager(engine, [
    createEscapeMenu, // 0
    createOutskirtsScene, // 1
    createBunkerScene, // 2
    createEndingScene // 3
]);
manager.setSceneIndex(0);
sceneManager.ts
// shared/sceneManager.ts - scenes are stored in an array
export class SceneManager {
    private current: Scene | null = null;

    constructor(
        private engine: Engine,
        private scenes: SceneFactory[]
    ) {
        // Only the active scene is rendered
        engine.runRenderLoop(() => {
            if (this.current?.activeCamera) this.current.render();
        });
    }

    setSceneIndex(index: number): void {
        if (this.switching) return;
        this.switching = true;
        // wait for the current frame to finish before disposing the old scene
        setTimeout(() => void this.load(index), 0);
    }

    private async load(index: number): Promise<void> {
        this.current?.dispose();
        const scene = await this.scenes[index](this.engine, this);
        await scene.whenReadyAsync();
        this.current = scene;
        this.switching = false;
    }
}

The old scene is disposed before the new one is created, which frees its meshes, sounds and GUI. setSceneIndex waits until the current frame has finished, because it is often called from inside the old scene's own update loop.

Switching from a GUI button

Menu buttons call setSceneIndex directly, for example START (gameState.reset() then scene 1), MAIN MENU (scene 0) and PLAY AGAIN on the rescue screen.

Switching from a scene event

outskirtsScene.ts
// Walking into the bunker door switches scene (outskirtsScene.ts)
const tryEnterBunker = () => {
    if (gameState.hasKeycard) {
        level?.finish();
        manager.setSceneIndex(SCENES.bunker);
    } else {
        hud.showMessage("LOCKED - FIND THE KEYCARD", 2.5);
    }
};

doorTrigger.actionManager = new ActionManager(scene);
doorTrigger.actionManager.registerAction(
    new ExecuteCodeAction(
        {
            trigger: ActionManager.OnIntersectionEnterTrigger,
            parameter: { mesh: player.hitbox, usePreciseIntersection: false }
        },
        tryEnterBunker
    )
);

An invisible box sits in front of the bunker door. Its ActionManager fires when the player's hitbox enters it. With the keycard, the controls are locked and the Bunker loads; without it, a message tells the player the door is locked. The radio at the end of the Bunker uses the same technique to load the rescue scene.

08

Audio

Audio starts off on every page and is turned on with the SOUND button. Browsers only allow sound after the user does something, so the button also unlocks Babylon's audio engine. Each scene keeps its sounds in a SoundBank: looping sounds (wind and music) start and stop with the SOUND setting, and effects play on events: picking up items, being hit, zombies groaning nearby and the bunker door opening.

outskirtsScene.ts / audio.ts
// shared/audio.ts - every sound for a scene in one place
const sounds = new SoundBank(scene)
    .add("wind", AUDIO.wind, { loop: true, volume: 0.6 })
    .add("music", AUDIO.music, { loop: true, volume: 0.45 })
    .add("pickup", AUDIO.pickup, { volume: 0.8 })
    .add("hit", AUDIO.hit)
    .add("groan", AUDIO.groan, { volume: 0.6 });

// The SOUND button turns audio on - this also unlocks the browser's audio
export function setAudioOn(on: boolean): void {
    audioOn = on;
    if (on) Engine.audioEngine?.unlock();
    listeners.forEach(listener => listener(on));
}
